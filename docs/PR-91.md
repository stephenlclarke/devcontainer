# PR 91: verify notary identity without changing credentials

## Implementation

The new manually dispatched workflow validates the exact main control SHA and the designated runner before loading the existing Apple ID and team secrets. Its single Python step compares their UTF-8 SHA-256 digests with fixed expected identities, emits only one fixed status per identity, and exits nonzero on either mismatch. It has read-only repository permissions, performs no checkout, and makes no keychain, notarization, network, build, signing, or release changes.

The README and this handoff document the read-only verification entry point and its boundary. The existing recovery workflow and its credential behavior remain unchanged.

## Validation and remaining gates

Actionlint and scoped Markdown lint pass. The inline Python passes five harmless-value cases covering matches, each identity mismatch, missing values and trailing whitespace; input values are absent from the output. The operator may dispatch the workflow only after this exact workflow source is merged to protected `main`.
