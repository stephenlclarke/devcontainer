# PR: avoid generic sleep specialization in the new event conflict retry

Change only the new event snapshot retry delay from `Task.sleep(for: .milliseconds(20))` to `Task.sleep(nanoseconds: 20_000_000)`, following the workaround reported in [Swift issue 86204](https://github.com/swiftlang/swift/issues/86204). The existing runtime request context already uses the nanosecond overload. The delay remains cancellation-aware and bounded at 20 ms. Retry count, complete snapshot identity proof, context checks, persistent-error behavior, and subscriber expiry checks stay unchanged. The existing 200 ms poll delay and the released SDK and lower layers stay unchanged.

Existing deterministic event regressions must continue to cover coherent retries, exact persistent-failure bounds, unrelated errors, cancellation, expired contexts, and subscriber expiry during a held retry. These assertions check semantics; they cannot establish that an optimized cross-module allocator failure has been eliminated. The actual failed signed startup is the release regression control. Fresh optimized exact-source gates, signed-package Apple stock startup, and all 84 runtime observations remain required. A reduced two-module optimized reproduction may independently compare generic and nanosecond retry variants, but absence of a crash there does not replace the actual packaged startup check. No new validation result is claimed by this proposal.
