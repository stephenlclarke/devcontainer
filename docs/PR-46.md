# Change handoff: use Docker-visible parity fixture workspaces

## Summary

Move copied devcontainer parity fixtures from the caller-selected evidence root to a marker-owned directory beneath the repository's `.build/parity-workspaces` directory. This makes the fixture source visible to Colima's Docker VM while preserving the resolved remote-workspace probe command and fail-closed cleanup.

## Motivation

The C04 Docker oracle's `devcontainer up` result correctly supplied `/workspaces/devcontainer-parity`, and the runner correctly selected that path before executing `probe.sh`. The fixture was nevertheless absent because the copy source was under `/private/tmp`, which Colima bound as an empty directory. The prior diagnosis treated this as an exec-forwarding issue; the retained manual bind inspection showed it was a Docker-visible-root issue instead.

## Implementation

- Leave `engine` fixtures untouched and run them without a copied devcontainer workspace.
- Copy each devcontainer fixture below `<repository>/.build/parity-workspaces/<fixture>-*/<fixture>`.
- Write an exact marker before the copy, then remove only a non-symlink, marker-matching child of that exact parent after the fixture's Docker cleanup.
- Preserve the existing absolute `remoteWorkspaceFolder` selection and shell probe invocation.
- Report a workspace cleanup refusal as a fixture failure rather than deleting an uncertain path.

## Validation

```console
python3 Tools/parity/test_run_lane.py
python3 -m py_compile Tools/parity/run_lane.py Tools/parity/test_run_lane.py
DEVCONTAINER_DOCKER_BIN=/private/tmp/devcontainer-c04-mount-3d0b6f9.K4fuzR/bin/docker \
  DEVCONTAINER_PARITY_FIXTURES=C04-compose-lifecycle \
  python3 Tools/parity/run_lane.py docker \
  /private/tmp/devcontainer-c04-mount-3d0b6f9.K4fuzR/evidence
```

Results:

- 24 focused parity-runner tests pass.
- Focused coverage exercises the newly added workspace copy, error, refusal, cleanup, and engine-fixture bypass paths; only five legacy `run_fixture` command-failure lines remain uncovered.
- The pinned Docker C04 oracle passed in 4.337 seconds using `@devcontainers/cli@0.88.0` (reference `f683c29f64a20109b4453e5149807e390ff65133`), Docker Engine 29.2.1/API 1.53, and Docker Compose 5.3.1.
- All C04 lifecycle observations pass: primary service and label selection, recreate, termination signal, restart, shutdown, and cleanup.
- The runner removed its `.build/parity-workspaces` copy root and left no matching Docker local-folder labels.

## Compatibility

The change is limited to disposable parity-fixture storage. It does not alter the Dev Containers CLI, user workspace locations, Engine API, Docker socket behavior, or container-compose implementation. Cleanup is narrower than before: it requires the expected parent and marker before deleting any copied fixture root.
