# Change handoff: select the service executable from the active SwiftPM build

## Summary

Rank fallback `devcontainer-engine` candidates by whether their coverage or non-coverage build path matches the active test bundle. This prevents a retained coverage binary from shadowing the service product built for a normal debug test run.

## Motivation

The new private-provider-session subprocess test exposed that `engineExecutable()` always sorted coverage products first. The test therefore launched an older instrumented binary and reported `--provider-socket` as unknown even though the current debug product accepted it.

## Implementation

- Derive the expected build kind from the active test executable and bundle paths.
- Prefer candidates whose coverage classification matches that build kind.
- Retain deterministic path ordering within the matching class.
- Preserve the explicit `DEVCONTAINER_ENGINE_TEST_EXECUTABLE` override and the existing sibling search.

## Compatibility

This change affects only test executable discovery. It does not change the installed CLI, Docker API behavior, runtime state, provider identity, or compatibility claims.
