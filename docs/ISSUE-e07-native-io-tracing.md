# Diagnose E07 native init-attachment stalls without changing parity evidence

The current E07 second-generation duplex probe can accept four MiB on the host socket, half-close input, and still wait at the unchanged output deadline. Host acceptance does not establish that the guest consumed all input. The native-only controller also stopped after a functionally failed first provider even when its exact runtime restoration and CLI cleanup were complete, preventing collection of the other provider's boundary evidence.

Add a bounded, explicit E07-only trace that records byte totals, EOF state and process/drain completion without logging payload, paths or provider identities. Per-chunk input logging risks changing the timing of the duplex race, and a cancelled stream may never reach the normal final EOF summary. Use MiB progress watermarks, retain exact terminal totals, and record a one-time cancellation summary before closing descriptors. Preserve the original deadlines and assertions, label traced timing diagnostic-only, and continue to the second provider only when both initial API preflight and the previous lane's CLI cleanup/restoration are confirmed. Any functional failure remains a failed diagnostic; uncertain restoration or preflight failure must still stop the campaign.
