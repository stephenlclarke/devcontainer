# Pull request 75: Docker-free Dev Containers adapter

## Summary

This change packages the official Dev Containers CLI above an Apple-native
compatibility boundary. It supports unmodified stock Apple `container` and an
explicit enhanced Container distribution without making Docker, an external
Compose installation, or a custom runtime an installation dependency.

It implements and release-gates the Engine API, Docker CLI, Compose, lifecycle,
stream, archive, build, network, volume, Feature-test, cleanup, fault-recovery,
and real VS Code paths used by the certified matrix. It also publishes the
complete architecture, user, conformance, performance, testing, quality,
installation, and release documentation.

## Implementation details

### Runtime and protocol boundary

- Bundles the checksum-pinned official `@devcontainers/cli` rather than forking
  its parser or lifecycle behaviour.
- Provides project-owned `devcontainer-docker` and `devcontainer-compose`
  compatibility entry points for the unmodified CLI and VS Code extension.
- Serves the required Engine API range from a project-owned Unix socket and
  translates requests directly to Apple-native operations.
- Authenticates the listening engine before the first workload request and
  rejects Docker socket names, symlink aliases, Docker-family executables, and
  foreign runtime provenance.
- Strictly decodes runtime-affecting requests and rejects unsupported semantics
  before resource creation.

### Stock and enhanced providers

- Keeps stock Apple `container` as the default and required release lane.
- Bundles an immutable stock-profile native `container-compose` executable for
  multi-service projects without importing `ComposeCore` into the neutral core.
- Allows the enhanced `stephenlclarke/container` distribution and an external
  `stephenlclarke/container-compose` only through explicit selection and exact
  source, version, and commit probes.
- Preserves process isolation so enhanced provider implementation details do not
  alter Apple's installed runtime or stock service graph.

### Correctness and safety

- Bounds provider probes, runtime readiness waits, process trees, request bodies,
  response bodies, archive transfer, guest hosts data, and cleanup.
- Preserves attached-process exit registration before start, forced-removal
  semantics, event time bounds, valid port ranges, full-duplex hijacked streams,
  large archive copies, Docker-compatible copy destinations, root-copy staging
  confinement, and tar option termination.
- Coalesces automatic-removal requests across a container's native ID, Docker
  ID, and name before scheduling deletion, while retaining the original
  creation timestamp so a same-name replacement cannot be removed. Native
  inventory probing runs only inside the background task and cannot delay a
  completed wait response.
- Uses a bounded metadata-only guest `stat` operation for archive `HEAD`
  requests, so destination discovery never materializes a populated directory.
- Preserves local symbolic links without following them, resolves remote
  destination links with cycle and depth bounds, and rebases literal tildes and
  hard-link targets using BSD tar's replacement grammar. Copy-out rejects a
  missing destination parent and preserves a dangling symbolic link when the
  destination gives it a new name.
- Normalizes Docker-ignore paths before negation interpretation and uses bounded
  Go-rune-compatible pattern matching, including literal escaped hyphens in
  character classes, rejection of every malformed class/range, trailing escape,
  and lone negation, slash members inside character classes, and scalar-accurate
  wildcards for decomposed Unicode names. Ignore files fail closed on read or
  UTF-8 errors and at Go scanner's 64 KiB token boundary, including an
  unterminated final line, while accepting an initial UTF-8 byte order mark like
  Docker's parser. Literal-only rules compare exact Unicode-scalar sequences in
  linear time without consuming the wildcard budget. All remaining wildcard
  matching shares a deterministic 33,554,432-work-unit build-context budget,
  including one charge for every character-class member scan, so valid
  near-limit patterns cannot multiply unbounded work across context entries.
- Prunes excluded non-symbolic-link directory subtrees during build-context
  enumeration when Docker's parent-exclusion semantics make descendant
  re-inclusion impossible, without pruning an ancestor of the explicitly
  selected Dockerfile or turning unavailable directory metadata into a build
  failure.
- Streams Dockerfile build archives from an owner-verified file in a mode-0700
  staging directory to the engine socket, avoiding an archive-sized client
  memory copy and removing the staging data on every return path.
- Spools Apple runtime copy-out archives to private mode-0600 files and serves
  them through a bounded pull stream, avoiding archive-sized service memory and
  removing each spool after completion or cancellation. Spools are created
  atomically with exclusive/no-follow flags, immediately unlinked, verified as
  owner-only anonymous regular inodes, and passed to writers and readers only
  as duplicated descriptors; pathname replacement and post-creation hard links
  cannot redirect, retain, or expose archive I/O.
- Applies one shared request deadline to native Compose project discovery and
  mutation child processes, including post-removal volume reconciliation, so a
  timed-out request cancels and reaps its owned process group.
- Fails Colima/Docker oracle preflight closed when the isolated reference daemon
  cannot be proved healthy.

### Packaging and supply chain

- Produces four signed commands, the official CLI payload, the stock-profile
  native Compose provider, both Linux volume initializers, the Apple CLI plug-in
  entry point, launchd metadata, build provenance, checksums, and notarization
  evidence.
- Vendors the exact Go module graph used by the provider build.
- Includes complete legal texts and SPDX 2.3 inventories for the primary Swift
  graph and the provider's Swift, Go, and Go-standard-library graph.
- Rejects missing, replaced, duplicated, stale, or unrecognized dependency
  metadata during package verification.

### Documentation and delivery

- Documents every confirmed non-conformance and separates candidate evidence
  from published stable claims.
- Marks the live 1.0.1 stable and Current Homebrew formulae as legacy,
  Docker-dependent packages so candidate installation examples cannot be
  mistaken for commands that satisfy the Docker-free contract before 1.0.2 is
  published.
- Records monotonic per-fixture timings and candidate-to-Docker ratios; ordinary
  slowness is diagnostic, while timeout, non-completion, invalid evidence, or a
  ten-times regression fails timing acceptance.
- Uses protected exact-commit CI, CodeQL, SonarQube, sanitizers, parity,
  Developer ID signing, notarization, release attestations, DocC Pages, and
  Homebrew verification before stable publication.
- Holds the Container family's shared host-wide runtime lock across every live
  CLI and VS Code parity lane so independently queued Compose work cannot
  invalidate quiet-host timing or runtime state.
- Configures SonarQube Previous version analysis with the exact commit SHA as
  the project version, making each analyzed commit compare with its predecessor.

## Compatibility

- Host: Apple silicon running macOS Tahoe 26 or later.
- Required runtime lane: unmodified Apple `container` 1.4.1 with
  `containerization` 0.45.0.
- Optional runtime lane: the exact enhanced Container-family distribution named
  by the parity manifest.
- Dev Containers: official CLI 0.89.0 and Dev Containers extension 0.470.0.
- VS Code: 1.137.0.
- Product boundary: no Docker, Docker Compose, Docker Desktop, Colima, Podman,
  nerdctl, or host daemon socket in an installed or candidate runtime path.

## Remaining risks

- Apple stock runtime limitations listed in `CONFORMANCE.md` remain explicit
  non-conformances rather than silent approximations.
- Provider fingerprints must be updated only after the selected stable
  `container-compose` tag is published and independently verified.
- Performance comparisons are valid only on the designated quiet host after
  competing Container-family release work has stopped.
- Stable publication remains blocked unless the exact release archive is
  Developer ID signed, accepted by Apple's notary service, and freshly installed
  from the generated Homebrew formula.
