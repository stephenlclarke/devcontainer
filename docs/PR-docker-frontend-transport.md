# PR: retain a bounded first-party Docker frontend transport

## Motivation and implementation

The enhanced dependency lacks the duplex transport declarations required by the first-party frontend. Four internal transport files adapt the stock API implementation at `40436017e1e93012b8dab7cfc3c79783538065c3`; original Apache-2.0 attribution remains in the sources and `NOTICE.md`. The frontend routes ordinary metadata requests, event/build streams and attach/exec upgrades through this compatibility client. Shared request, response and ordinary error types remain unchanged; the absolute-deadline case uses a local error because the enhanced profile lacks that enum case.

Cancellation shuts down the owned socket to interrupt blocked workers; worker-owned closure and lock-protected duplicated descriptors prevent descriptor-reuse races. The duplex path preserves buffered output, independently serializes each direction and half-closes stdin. Ordinary metadata remains capped at 30 seconds and interactive sessions retain the existing finite ceiling. Three source-format corrections also address the exact-head hosted Validate failures without changing behaviour.

Exec now parses standalone `-t`/`--tty` and common `-it`/`-ti` forms, carries TTY allocation through both Engine requests, and forwards TTY output as raw combined stdout. Interactive stdin remains controlled separately by `-i`. This implements the remote PTY pipeline supported by the API/runtime; local terminal raw-mode setup and resize forwarding remain outside this change.

## Validation

Real Unix-socket regressions exercise malformed upgrades, bounded server errors, head-adjacent bytes, concurrent output/input, half-close, unsafe paths and permissions, incomplete-header cancellation, response cancellation, trickling absolute deadlines, delayed timer delivery and concurrent close. The complete native Docker-client target passes in both stock and enhanced release profiles with `Tools/bazel/run.sh test --config=<profile> --config=release --config=prebuilt-container-sdk //:products //:DevContainerDockerClientTests`; the product target loads the complete selected dependency closure for strict origin verification. The real executable Unix-socket TTY regression failed against the original production source and passes with this fix. Its two cases verify terminal allocation, combined raw output, independent stdin attachment and half-close, and the remote exit status. Additional regressions cover standalone/bundled options, exact create/start Tty fields, fragmented raw terminal output containing a multiplex-header lookalike, and cancellation through raw output. Each profile passes all 110 test functions across 11 suites, including the final lint-only extraction of the boolean parser and terminal assertions. The stock accepted invocation is `449f178e-8939-4233-b8b5-6b51bf9d60e5`; the enhanced invocation is `2e22f5d4-f787-49b4-81bb-faf741d7595c`. Both commands also pass strict dependency-origin verification. Existing focused stock coverage is 431/472 client lines (91.3%), 590/636 lines across the four transport files (92.8%), and 1784/1853 Docker-client lines (96.3%); these predate the TTY follow-up and are not final aggregate release coverage. Independent earlier review found no socket ownership, deadline, framing or cleanup blocker. Failed draft, fixture-path and over-broad metadata-selection attempts remain retained as unqualified feedback.
