# Pull request handoff: fix(runtime): join pending owned start before live-reader admission

AppleContainerIO exposes a lock-protected pending-owned-start predicate excluding closed controls and native/completed exit. Shared prepareContainerIO joins a captured registered operation only when the running snapshot belongs to that exact channel incarnation and verification is still pending. After joining it refreshes and checks creation/Docker identity/terminal mode before retrying. No ownership guard is relaxed; start cannot meet the pending predicate until its own prepareContainerIO has returned.

The proposed parameterized regression holds the fake process start after native running publication and before confirmation, checks running/unowned state, exercises each of public attach, live attachment preparation and exit-wait registration while confirmation is held, then releases it and requires successful exact exit. Its 100-ms bounded observation catches the old early error while the held state is invariant; it is not a production timeout. Failure cleanup releases start, finishes the fake process and shuts down the fixture. Existing replacement=true and unmanaged-running tests remain unchanged.
