# Pull request handoff: fix(parity): bound E07 native init I/O diagnostics

The E07 native diagnostic can opt into payload-free stream tracing with `--trace-init-io`; the option is accepted only for the single E07 native diagnostic, forwarded explicitly into the admitted lane runner and recorded in operator inputs as diagnostic-only timing. Input progress is emitted only at MiB watermarks, while exact input/output totals, EOF state, process exit and drain result remain in synchronized terminal records. A one-time cancellation summary is written before descriptors are cancelled, preserving partial byte totals when EOF is absent. Progress output remains capped at 256 records per process generation; writes are serialized, and disabled tracing avoids counter and pending-write reads.

The native diagnostic controller now runs the second provider after a first-provider functional failure only when initial native API preflight succeeded and the first lane reports both `restored` and `cliCleanupComplete: true`. It preserves the functional failure in the final status. Failed preflight, uncertain restoration and incomplete CLI cleanup still stop execution. Full qualification ordering and behavior are unchanged.

Validation: the prior controller/lane run passed 151 Python tests, and the prior trace implementation passed the focused stock `DevContainerAppleRuntimeTests` target. New Swift regressions now assert MiB input watermarks, exact cancellation summaries and zero pending-write reads when tracing is disabled. For this follow-up, SwiftFormat and source/Markdown checks are run without Bazel or runtime work; the new Swift tests await the next authorized focused target run. Traced timing remains diagnostic evidence only.
