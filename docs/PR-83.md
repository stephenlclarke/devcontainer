# Pull request 83: native Bazel build and evidence retention

## Motivation

Implement the native compilation/test boundary of the approved build-workflow redesign before replacing production CI and release paths. Tracked against [the workflow issue](ISSUE-build-bazel-workflow.md) and [PR 83](https://github.com/stephenlclarke/devcontainer/pull/83). This is continuing implementation of the complete system, not a claim that the initial qualification finishes the goal.

## Implementation

- Pin verified Bazel tooling and native Swift/SQLite targets with declared generated version inputs.
- Enroll and validate SSD storage; isolate download/cache/output/test scratch paths.
- Adapt upstream test-source/XML writes for external-volume sandbox compatibility and export/merge native Swift coverage from the original test execution.
- Add version-generator and launcher regressions, evidence validation and opt-in Make targets.
- Import the exact stock/enhanced package pins as native dependency targets; build all three project executables and ten unit-test targets.
- Separate real Keychain and Apple-service tests into explicit uncached host targets; preserve the ordinary source suites in both profiles.
- Keep test fixtures on SSD and inject direct/fallback fake-runtime transfer storage without changing production daemon-sharing defaults. The runtime initializer also accepts an explicit transfer root for callers that own a daemon-accessible scratch directory.
- Use sibling-file atomic replacement for writes that Foundation otherwise stages outside the destination volume sandbox.
- Preserve downloaded hosts-file permissions when editing private transfer staging; this disposable copy needs no atomic replacement.
- Seal source identity, build events, XML, LCOV and outcome bytes in transactional internal storage with content deduplication. Serialize each workspace through retention; fail mixed-source or conflicting evidence.
- Bound Bazel's native disposable cache and reject dependency/environment overrides that would break the pinned/storage contract.
- Isolate inherited credentials from Bazel and its event stream, preserve only validated host-test opt-in, and distinguish query/info diagnostics from build evidence.
- Add native optimized candidate archiving with the existing deterministic archive writer, digest-bearing metadata, transactional internal retention and authenticated SSD restore without rebuilding.
- Acquire reviewed GitHub binary assets with exact release/tag/commit/asset identity and checksum verification, durable pending/sealed ingest and explicit offline reuse, without compiling references.
- Register invocation ownership and add conservative leased cleanup of expired, internally retained scratch. Keep unknown/legacy directories, runtime services and GitHub resources untouched.
- Export authenticated retained LCOV as Sonar generic XML with unchanged line counts, explicit original source identity and no build/test execution. Reject corrupt, dirty, incomplete or mismatched receipts; do not silently submit historical evidence as current-head coverage.
