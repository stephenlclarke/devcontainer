# PR: retry complete event inventory observations after explicit conflict

Event startup and polling use a shared bounded snapshot read: at most three full inventory calls, separated by a cancellation-aware 20 ms delay, only for the exact CLI-inventory identity-conflict code and message. A retry accepts only a newly coherent complete snapshot through the unchanged identity proof. No partial row is accepted and no timestamp comparison is loosened. Persistent conflicts and every unrelated error remain terminal; request context and task cancellation are checked before and after acquisition.

Deterministic actor-backed offline regressions cover initial conflict recovery, polling conflict recovery with one start event, exactly bounded persistent failure, immediate unrelated errors, cancellation and expired context. An explicit actor barrier holds the retry until its subscriber expires; the stream must then end without a late event. The new regressions failed against the original implementation in retained invocation `791c1896-7f68-4c89-b084-70fa5e01087f` (316 tests, eight issues in seven new test cases); the corrected stock runtime suite passed in retained invocation `77114f3d-bf70-4d96-8919-173dfb96b2ce`. Removing only the expiry recheck reproduces exactly one late-event failure in retained invocation `660f65cb-d29e-42c3-9020-8d67f023f117`; the retry behavior remains enabled in that regression control. Exact-source native gates and fresh finalized-package runtime qualification remain required before release readiness. No lower Engine API transport change or dependency rebuild is proposed.

The stock runtime suite also passes after extraction in retained invocation `51e102ad-ef5d-4a06-a083-3c93980165f6`. The event poller is kept in its own companion source file so its existing private state and retry helper stay encapsulated within the lint file-size limit. The runtime-facing extension retains its existing API.
